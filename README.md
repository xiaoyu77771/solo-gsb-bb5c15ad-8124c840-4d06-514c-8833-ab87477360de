# 话剧走位连续性检查

一个用于检查话剧/舞台剧**换场走位连续性**的 Web 应用：在带通行秒数的舞台区域邻接图上，按场次录入换场时长与每位演员的起止位置，并为相邻场次设置不可穿越区域；系统自动计算转场可达性，**定位首个不可能转场**，并展示最短耗时路径或阻断原因。

技术栈：Node.js + Express + SQLite（better-sqlite3）+ 原生 HTML/CSS/JS（无任何前端构建步骤）。

## 一、启动（单条命令）

```bash
docker compose up --build
```

依赖安装（镜像构建时 `npm ci`）与数据库初始化（首次启动自动建表并写入示例剧目《茶馆》）均随启动自动完成。

- **访问地址**：http://localhost:3000
- **端口**：`3000`（宿主机端口可在 `docker-compose.yml` 的 `ports` 中调整，如 `"8080:3000"`）

停止：`docker compose down`（数据保存在命名卷 `app-data` 中，重启不丢失；`docker compose down -v` 会连同数据一起删除）。

## 二、配置（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 应用监听端口 |
| `DB_PATH` | 容器内 `/app/data/app.db`；本地运行为 `./data/app.db` | SQLite 数据库文件路径 |

本地开发（不使用 Docker）：

```bash
npm install
npm start          # 或 npm run dev（文件变动自动重启）
```

## 三、功能说明

1. **舞台区域图**：添加/重命名/删除舞台区域（节点可拖拽布局）；在区域间添加带**通行秒数**的邻接边（点击图中的边或列表中的「改秒数」可修改）。
2. **场次与换场**：按顺序维护场次；相邻两场之间自动生成一个换场，可设置：
   - 换场时长（秒）；
   - 本次换场期间的**不可穿越区域**（如布景吊装区）；
   - 每位演员的**起点 → 终点**走位表。
3. **检查结果**：点击「运行检查」（自动先保存），系统对每个换场、每位演员在剔除不可穿越区域后的图上求最短耗时路径（Dijkstra）：
   - 全部可行 → 绿色提示；
   - 存在失败 → 红色标出**首个不可能转场**，逐演员给出最短路径与耗时，或阻断原因（超时 / 区域不连通 / 起终点落在不可穿越区域）。
4. **保存与导出**：「保存全部」持久化当前剧目；「导出 JSON / 导出报告」下载机器可读结果或纯文本检查报告。首次启动自带示例剧目《茶馆》，其中第二幕→第三幕被设计为不可能转场，可直接体验检查效果。

## 四、API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/plays` | 剧目列表 |
| POST | `/api/plays` | 新建剧目 `{name}` |
| GET | `/api/plays/:id` | 剧目完整文档（区域/边/场次/换场/走位） |
| PUT | `/api/plays/:id` | 整剧保存（完整文档，事务内按 id 保留/增删） |
| DELETE | `/api/plays/:id` | 删除剧目（级联删除全部关联数据） |
| GET | `/api/plays/:id/check` | 运行连续性检查，返回 JSON 结果 |
| GET | `/api/plays/:id/export?format=json\|txt` | 导出检查结果（JSON 或文本报告） |
| GET | `/api/health` | 健康检查 |

## 五、目录结构

```
server.js      Express 服务与 REST API
db.js          SQLite 连接与建表
check.js       核心算法：邻接图构建 + Dijkstra 最短路径 + 逐换场检查
seed.js        首次启动写入示例剧目
report.js      文本检查报告生成
public/        原生前端（index.html / app.js / style.css）
Dockerfile     单阶段镜像（依赖安装于构建期，数据库初始化于启动期）
docker-compose.yml
```
